##### Personas
Una entidad ficticia que representa un usuario destino. Están representadas por rasgos y cualidades de usuarios reales. Puede representar información de:

- Nombre.
- Imagen(Foto, Avatar, etc.).
- Información de sus rasgos de usuario como: Información demográfica, situación, estatus de empleo que ayuden a entender información relevante para el producto o espacio del problema.
- Sus necesidades y objetivo en relación con el producto.
- Resumen de desafíos, deseos o preocupaciones en relación con el producto.

Tener personas consideradas como parte de la solución del producto ayuda a entender y tomar decisiones con respecto al producto.

##### Historias de usuario
Da a una [[Computo/Conceptos/Diseño/User Experience/Conceptos| Persona]] el contexto de su problemática y deseos para tratar de dar respuestas al que y para que el producto podría ser utilizado:

'Como una *persona* quiero acceder a una dieta mas saludable, porque solo así podre acceder a un bienestar físico mejor que mi actual estado físico'.

Se enfoca en como el usuario conseguiría lidiar con su problemática.

##### Escenario de usuario
Se trata de posibles interacciones que un usuario podría tener con el producto y puede ser dividido en diferentes casos de uso.

##### Casos de uso
Aquel enfoque en las interacciones que el usuario tiene con el producto. Cada caso de uso del usuario debería ser registrado y almacenado como información del uso del sistema.
- Nombre y numero de identificación de caso de uso.
- Descripción.
- Usuarios/Actores.
- Status: Información acerca del progreso acerca del propio caso de uso:  En progreso, listo para ser revisado, bajo revision, rechazado o aceptado.
- Casos relacionados: Información de los casos de uso relacionados al caso de uso actual.
- Precondiciones: Todas las condiciones necesarias para que el caso de uso sea posible emerja.
- Postcondiciones: El estado resultado del caso de uso emergido.
- Flujo estándar: Representa el conjunto de interacciones que un actor comúnmente tiene con el producto.
- Flujo alternativo: Escenarios que ocurren fuera del flujo estándar durante el cumplimiento de una tarea con el producto.
- Indicios: Información adicional de las interacciones o condiciones del usuario sobre el entorno donde el producto fue utilizado.
- Historial de cambios: Información de fecha y revision sobre el caso de uso registrado.
